# KAN-160 — Mask customer phone numbers and keep an audit trail

## 1. Ticket
- **Key:** KAN-160
- **Title:** Mask customer phone numbers and keep an audit trail
- **Requester:** Swayam Barik
- **Link:** https://demo-ibm-bob.atlassian.net/browse/KAN-160

## 2. What I understood
The daily report currently prints customer phone numbers in full. Compliance requires that phone numbers be masked before they appear in any printed output. Additionally, every assign and every close action must be recorded in an append-only audit log so that compliance can trace who changed which order and when. A new `audit.py` module will provide wrapper functions for assign and close; the existing `assign.py` and `store.py` files must not be changed.

## 3. Design decisions
| # | Question | Answer | Effect |
|---|----------|--------|--------|
| 1 | Masking pattern | **default** — mask everything after the second hyphen → `415-555-****` | `report.py` will apply a helper that replaces the last segment with `****` |
| 2 | Audit log location | **default** — `fieldops-repo/data/audit.log` | `audit.py` opens and appends to that path |
| 3 | Audit log format | **default** — `ISO-timestamp \| who \| order_id \| change` | One line per event, e.g. `2026-10-19T19:28:00Z \| dispatcher1 \| 42 \| assigned crew B` |
| 4 | Missing `who` value | **default** — record `"unknown"` if omitted or empty | Wrappers accept optional `who` parameter, default `"unknown"` |

## 4. Open questions
None.

## 5. Acceptance criteria
- [ ] The daily report shows every phone number as `NXX-NXX-****` (area code and exchange visible, last four digits replaced with `****`). No full number appears in the output.
- [ ] `fieldops/audit.py` exists and exposes `assign(order_id, crew_id, who="unknown")` and `close(order_id, who="unknown")` wrappers.
- [ ] Calling `audit.assign(...)` or `audit.close(...)` appends exactly one line to `data/audit.log` in the format `ISO-timestamp | who | order_id | change`.
- [ ] The audit log file is only ever appended to; existing lines are never modified or deleted.
- [ ] `python -m pytest tests/test_report.py tests/test_audit.py` passes with no errors.
- [ ] Running `python -m fieldops.report` produces output with no full phone number.

## 6. Test plan
| Criterion | Test file | What the test checks |
|-----------|-----------|----------------------|
| Phone masking in report | `fieldops-repo/tests/test_report.py` | `daily_report()` output contains no string matching `\d{3}-\d{3}-\d{4}` |
| `audit.assign` appends a line | `fieldops-repo/tests/test_audit.py` | After calling `audit.assign(id, crew, who)`, `data/audit.log` gains one line containing the order id, crew, and who |
| `audit.close` appends a line | `fieldops-repo/tests/test_audit.py` | After calling `audit.close(id, who)`, `data/audit.log` gains one line containing the order id and who |
| Log is append-only | `fieldops-repo/tests/test_audit.py` | Two consecutive calls produce two new lines; existing lines are unchanged |
| Default `who` | `fieldops-repo/tests/test_audit.py` | Calling wrappers without `who` writes `unknown` in the log line |

## 8. Out of scope
- Changing `fieldops/assign.py` or `fieldops/store.py`.
- Wiring the web UI (`app.py`) to the audit wrappers (follow-up ticket).
- Masking phone numbers in stored CSV data.
- Log rotation or archiving.

## 9. Risk and compliance
- Phone numbers: masked in report output; never printed in logs or test output. Raw data in CSV is unchanged and not exposed by this ticket.
- Secrets: none involved.
- Data loss: audit log is append-only; no existing data is modified.
- Rollback: revert `report.py` and delete `audit.py`; no schema changes needed.
