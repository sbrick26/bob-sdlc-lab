## 2. What I understood
The crew assignment module (`fieldops/assign.py`) currently has no test coverage. We need to add comprehensive tests in `tests/test_assign.py` and set up test isolation in `tests/conftest.py` to lock in all existing assignment rules, load calculations, priority logic, and edge cases without modifying any production code or data files.

## 3. Design decisions
- Question 1 (Test isolation and fixtures): Default. Redirect `store.ORDERS_FILE` and `store.CREWS_FILE` in `tests/conftest.py` using `tmp_path` and `monkeypatch` so tests never alter live CSV data.
- Question 2 (Scope of test cases): Default. Create comprehensive unit tests in `tests/test_assign.py` covering `crew_load`, `pick_crew`, and `assign_order` across all branches and priority levels.
- Question 3 (Handling legacy quirks): Default. Strictly assert current module behavior in tests and document quirks in test docstrings without altering production code.

## 4. Open questions
None.

## 5. Acceptance criteria
- `python -m pytest` passes with all tests green.
- Priority 1 orders assign the home crew regardless of crew skills.
- Priority 2 orders assign the home crew only when the crew has matching equipment skills.
- Orders with missing or empty sites fall back to the first available crew with matching skills.
- Orders with unknown equipment or when all crews are at capacity (`load >= 4`) fall back to Crew A.
- `assign_order` successfully assigns open orders to valid crews and rejects invalid crews, missing orders, or closed orders.
- No files in `fieldops/` or `data/` are modified.

## 6. Test plan
- Test file: `fieldops-repo/tests/test_assign.py`
- Test functions:
  - `test_crew_load_calculation`: Verifies load count calculation from order lists.
  - `test_pick_crew_unknown_equipment`: Verifies fallback to Crew A for unknown equipment.
  - `test_pick_crew_all_busy_overflow`: Verifies fallback to Crew A when all crews reach MAX_LOAD.
  - `test_pick_crew_priority_1_home_crew`: Verifies Priority 1 selects home crew even without matching skill.
  - `test_pick_crew_priority_2_home_crew_matching_skill`: Verifies Priority 2 selects home crew with matching skill.
  - `test_pick_crew_priority_2_home_crew_no_skill_fallback`: Verifies Priority 2 falls back when home crew lacks skill.
  - `test_pick_crew_no_site_skill_fallback`: Verifies order with no site falls back to first free skilled crew.
  - `test_assign_order_success`: Verifies successful order assignment and status update.
  - `test_assign_order_invalid_crew`: Verifies rejection when assigning to non-existent crew.
  - `test_assign_order_closed_or_missing`: Verifies rejection when order is closed or does not exist.
