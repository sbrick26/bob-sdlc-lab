## 2. What I understood

The crew assignment rules in `fieldops/assign.py` (`pick_crew`, `assign_order`, `crew_load`) have no tests, and nobody dares to change them. I will add tests that record what the code does today, including its odd behaviour, so the next person can change it safely. I will not change how anything behaves. If something looks wrong, I write it down in the change note and do not fix it. No file in `fieldops/` or `data/` changes.

## 3. Design decisions

1. Coverage: the four cases the ticket asks for, plus every other branch in `assign.py` (priority 2 rule, unknown equipment, all crews busy, `crew_load`, `assign_order`). Answer: default. This locks in the whole file, not just four rules.
2. Odd behaviour: each odd case gets a test named for what it does today, with a one-line comment. The cases are also listed under "Observations, not fixed" in `fieldops-repo/changes/KAN-157.md`. Answer: default. Nothing is fixed; the tests describe current behaviour even where it looks wrong.
3. Test data: `pick_crew` and `crew_load` tests use crew and order dicts built in the test. `tests/conftest.py` has one fixture that writes small temp CSV files with made-up data and points `store.ORDERS_FILE` and `store.CREWS_FILE` at them. `assign_order` tests use that fixture. Answer: default. The real CSVs and the real customer data are never read or written.

## 5. Acceptance criteria

- `python -m pytest` runs green from `fieldops-repo/`.
- A test shows that for a priority 1 order with a site, the free home crew is picked even if it lacks the skill.
- A test shows the site rule for priority 2 (home crew only if it has the skill), and a test shows the skill fallback (first free crew in file order with the skill).
- A test shows what happens to an order with no site, and the change note records it as an observation.
- Tests also cover unknown equipment, all crews busy, `crew_load`, and `assign_order` (valid crew, unknown crew, closed order, missing order).
- `git diff` shows no change under `fieldops-repo/fieldops/` or `fieldops-repo/data/`.

## 6. Test plan

All tests are in `fieldops-repo/tests/test_assign.py`; the fixture is in `fieldops-repo/tests/conftest.py`.

- Green run: `python -m pytest` and `python -m pytest tests/test_assign.py -v`.
- Priority 1 home crew first: `pick_crew` tests with a home crew that has and one that lacks the skill.
- Site rule and skill fallback: `pick_crew` tests for priority 2 with and without the skill, and priority 3 falling to the first free crew with the skill.
- No site: `pick_crew` tests with an empty site and a missing site for priority 1 and 2.
- Other branches: tests for unknown equipment, all crews busy (load 4 or more), and `crew_load` counting only assigned orders.
- `assign_order`: tests using the temp CSV fixture for valid, unknown crew, closed order and missing order.
- No change to `fieldops/` and `data/`: checked with `git diff --stat` in review.
