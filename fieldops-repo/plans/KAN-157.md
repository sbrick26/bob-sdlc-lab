## 2. What I understood

The crew assignment logic in `fieldops/assign.py` has no tests and no one dares touch it. This ticket adds a characterisation test suite — tests that pin the current behaviour exactly as-is, including known quirks. Nothing in `fieldops/` or `data/` changes. If something looks wrong it gets a comment in the test, not a fix.

## 3. Design decisions

| # | Question | Answer | Effect |
|---|----------|--------|--------|
| 1 | `conftest.py` fixture scope | default — **function-scoped** | Each test gets a fresh temp file; full isolation, no bleed between tests |
| 2 | Observing the known site-missing bug | default — **assert current behaviour, add a comment** | The test for an order with no site asserts that skill-fallback runs (home-crew rule skipped), with an inline comment noting the 2014 TODO |
| 3 | `conftest.py` existence | default — **create as a new file** | `fieldops-repo/tests/conftest.py` will be created alongside the test file |

## 4. Open questions

None.

## 5. Acceptance criteria

- `python -m pytest fieldops-repo/tests/test_assign.py -v` exits green with no errors.
- There is a test for the priority-1 rule: the home crew is chosen even without the required skill.
- There is a test for the priority-2 / site rule: home crew is chosen only when they have the skill.
- There is a test for the skill fallback: when no home-crew match exists, the first free crew in file order with the skill is returned.
- There is a test for an order with no site: the current behaviour (skill-fallback, home-crew rule skipped) is asserted and the known issue is noted in a comment.
- No file under `fieldops-repo/fieldops/` or `fieldops-repo/data/` is changed.

## 6. Test plan

All criteria are proved by `fieldops-repo/tests/test_assign.py`:

| Criterion | Test function |
|-----------|---------------|
| Priority-1 home crew | `test_pick_crew_priority1_home_crew` |
| Priority-2 site + skill | `test_pick_crew_priority2_home_with_skill` |
| Skill fallback | `test_pick_crew_skill_fallback` |
| No site | `test_pick_crew_no_site` |
| `assign_order` returns True on valid input | `test_assign_order_valid` |
| `assign_order` returns False for unknown crew | `test_assign_order_unknown_crew` |

`conftest.py` at `fieldops-repo/tests/conftest.py` provides the function-scoped temp-file fixture used by `test_assign_order_*` tests.

## 7. Work units

```
fieldops-repo/tests/test_assign.py     ← create (new file)
fieldops-repo/tests/conftest.py        ← create (new file)
```

## 8. Out of scope

- Fixing any bug in `assign.py` (the 2014 missing-site issue, overflow logic, etc.).
- Tests for `store.py`, `report.py`, or any other module.
- Changes to CSV data files.
- CI configuration changes.

## 9. Risk and compliance

- No personal data is read or written by the tests; `conftest.py` uses an empty temp file.
- No secrets involved.
- No data loss risk; production CSV files are never touched.
- Rollback: delete the two new test files.
