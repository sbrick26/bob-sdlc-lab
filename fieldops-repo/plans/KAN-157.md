# KAN-157 — Lock in what the crew assignment service does today

## 1. Ticket
- **Key:** KAN-157
- **Title:** Lock in what the crew assignment service does today
- **Requester:** Swayam Barik
- **Link:** https://demo-ibm-bob.atlassian.net/browse/KAN-157

## 2. What I understood
The crew assignment logic in `fieldops/assign.py` has no tests. Anyone who needs to change it has no safety net. This ticket adds a pytest test file that characterises the existing behaviour of `pick_crew`, `assign_order`, and `crew_load` exactly as they work today. Tests must not alter any file under `fieldops/` or `data/`. If the code contains quirks or apparent bugs, they are documented as comments in the test file — not fixed.

## 3. Design decisions
1. **conftest.py scope** — asked whether to use `tmp_path`-based per-test patching or a session-scoped temp dir. **Default accepted:** `tmp_path` fixture that monkeypatches `store.ORDERS_FILE` and `store.CREWS_FILE` per-test (function scope).
2. **Documenting observed quirks** — asked whether to record quirks in the test file or a separate note file. **Default accepted:** comment in `tests/test_assign.py` above the relevant test, prefixed with `# NOTE (observed behaviour):`.
3. **Test file location for conftest** — asked whether conftest goes in `tests/conftest.py` or is inlined in the test file. **Default accepted:** `tests/conftest.py` (standard pytest location, reusable by future test files).

## 4. Open questions
None.

## 5. Acceptance criteria
- [ ] `python -m pytest tests/test_assign.py -v` exits green with no errors.
- [ ] There is a test proving the priority-1 rule: the home-site crew is returned even if it lacks the skill.
- [ ] There is a test for the site rule at priority 2 (home crew returned only when it has the skill).
- [ ] There is a test for the skill fallback (no site, first free crew with the skill wins).
- [ ] There is a test for an order with no site (site rules are skipped; skill fallback or default crew is used).
- [ ] No file under `fieldops/` or `data/` is created, modified, or deleted.

## 6. Test plan
| Criterion | Test | File |
|-----------|------|------|
| pytest exits green | all tests pass | `fieldops-repo/tests/test_assign.py` |
| Priority-1 home-crew rule | `test_pick_crew_priority1_home_site` | `fieldops-repo/tests/test_assign.py` |
| Priority-2 site + skill rule | `test_pick_crew_priority2_home_site_with_skill` | `fieldops-repo/tests/test_assign.py` |
| Skill fallback | `test_pick_crew_skill_fallback` | `fieldops-repo/tests/test_assign.py` |
| No-site order | `test_pick_crew_no_site` | `fieldops-repo/tests/test_assign.py` |
| fieldops/ and data/ untouched | checked by test isolation via conftest monkeypatch | `fieldops-repo/tests/conftest.py` |

## 7. Work units
```
fieldops-repo/tests/conftest.py        # new – monkeypatches store.ORDERS_FILE and store.CREWS_FILE to tmp_path copies
fieldops-repo/tests/test_assign.py     # new – characterisation tests for pick_crew, assign_order, crew_load
```

## 8. Out of scope
- Fixing any existing bugs or quirks in `assign.py`.
- Adding tests for any module other than `assign.py`.
- Changing `fieldops/store.py`, `fieldops/assign.py`, or any file under `data/`.
- Integration or end-to-end tests.

## 9. Risk and compliance
- No personal data is read or written in tests; crew and order dicts are built inline.
- No secrets or credentials involved.
- `data/` and `fieldops/` files are never touched; monkeypatching is function-scoped so there is no cross-test contamination.
- Rollback: delete `tests/conftest.py` and `tests/test_assign.py`.
