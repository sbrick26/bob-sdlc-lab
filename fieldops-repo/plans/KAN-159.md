### 2. What I understood
Dispatch needs to manage work orders conversationally in plain words using an MCP server called from Bob IDE without using the web UI for simple tasks. We will create an MCP server in `fieldops/mcp_server.py` using `mcp` (FastMCP) exposing three tools: `list_orders(site, status)`, `assign_order(id, crew)`, and `close_order(id)`. The server will delegate all domain logic to `fieldops.store` and `fieldops.assign`, support optional filtering and sorting (priority ascending, created date ascending), mask customer phone numbers for data privacy, and include full test coverage in `tests/test_mcp_server.py`.

### 3. Design decisions
- Decision 1 (PII and Data Masking): Mask customer phone numbers as `415-555-****` in order listings and omit unneeded customer PII to comply with project privacy rules. Answer: default.
- Decision 2 (Filtering and Sorting): `list_orders` supports optional `site` and `status` filters, sorting results by priority ascending (lowest number first) then oldest `created` timestamp. Answer: default.
- Decision 3 (Return Format & Error Handling): `assign_order` and `close_order` return structured result summaries and handle nonexistent orders or invalid crew assignments gracefully. Answer: default.

### 5. Acceptance criteria
- An MCP server in `fieldops.mcp_server` provides three tools: `list_orders(site, status)`, `assign_order(id, crew)`, and `close_order(id)`.
- `list_orders` filters correctly by site and status when provided and sorts orders by priority (lowest number first), then created timestamp (oldest first).
- `assign_order` validates crew existence and assigns orders using existing logic in `fieldops.assign`.
- `close_order` closes the order using `fieldops.store` and reflects on the web UI and CSV storage.
- Customer phone numbers are masked as `415-555-****` in tool outputs.
- `python -m pytest tests/test_mcp_server.py` runs green with all tests passing.

### 6. Test plan
- Unit tests in `fieldops-repo/tests/test_mcp_server.py` verifying `list_orders` filtering and sorting, `assign_order` success and validation failures, `close_order` functionality, and phone number masking without altering source data files.
