# Plan format (plans/<KEY>.md)

Use exactly these headings, in this order. Short sentences. A requester must be able to read it in two minutes.

1. Ticket: key, title, requester, link.
2. What I understood: one paragraph in plain words.
3. Open questions: at most two. Each with a default answer. Say "none" if none.
4. Acceptance criteria: 3 to 6 bullets, each one checkable by a non-developer.
5. Test plan: which tests prove each criterion. Name the test file.
6. Work units: the files to create or change, one line each. Nothing else may change.
7. Out of scope: what this ticket does not do.
8. Risk and compliance: personal data, secrets, data loss, rollback. One line each or "none".
9. Approval: "Requester approval: pending" until the requester approves.
