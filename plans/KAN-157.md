## 2. What I understood
The crew assignment code in `fieldops/assign.py` has no tests, so nobody dares change it. I will add tests that record what it does today, including the odd cases. I will not change `fieldops/` or `data/`. If a rule looks wrong, I note it in the PR change log and do not fix it. The tests must not touch the real CSV files.

## 3. Design decisions
1. Test location and imports: default. Create `tests/conftest.py` and `tests/test_assign.py`. `conftest.py` adds the repo root to `sys.path`, so `pytest.ini` stays untouched.
2. Isolating CSV writes: default. An autouse fixture in `tests/conftest.py` writes small hand-built crews and orders CSVs into `tmp_path` and points `store.ORDERS_FILE` and `store.CREWS_FILE` at them with `monkeypatch`. `pick_crew` and `crew_load` tests use plain dicts. The real `data/` files are never read or written.
3. What gets locked in: default. Current behaviour only, including the odd parts (see criteria). Nothing is fixed.
4. Where "looks wrong" notes go: default. Under Risk below and in line 2 of `changes/KAN-157.md`. No extra docs.

none

## 5. Acceptance criteria
- `python -m pytest` runs green.
- A test shows that for a priority 1 order with a site, the home crew is picked even without the skill.
- A test shows the site rule (priority 2: home crew only if it has the skill) and a test shows the skill fallback (first free crew in file order with the skill).
- A test shows that an order with no site skips the site rules and uses the skill fallback.
- Tests also cover unknown equipment and all crews busy (both give crew A), `crew_load` counting only assigned orders, and `assign_order` success, unknown crew, missing order and closed order.
- No file in `fieldops/` or `data/` changed, and the real CSV files are not modified by the tests.

## 6. Test plan
All in `tests/test_assign.py`, with fixtures in `tests/conftest.py`:
- Green run: `python -m pytest tests/test_assign.py -v`, then `python -m pytest`.
- Priority 1 home crew: `test_priority_1_home_crew_goes_first_without_skill`.
- Site rule and fallback: `test_priority_2_home_crew_needs_skill`, `test_skill_fallback_first_free_in_file_order`.
- No site: `test_no_site_skips_site_rules`.
- Defaults: `test_unknown_equipment_goes_to_crew_a`, `test_all_busy_goes_to_crew_a`.
- Load: `test_crew_load_counts_only_assigned`.
- Assign: `test_assign_order_ok`, `test_assign_order_unknown_crew`, `test_assign_order_missing_order`, `test_assign_order_closed_order`.
- No change to code or data: `git diff --stat` shows only the files in the work units.

## 7. Work units
- `tests/conftest.py` (create): sys.path setup and the temp CSV fixture.
- `tests/test_assign.py` (create): the tests above.
- `changes/KAN-157.md` (create): line 1 ticket and what changed, line 2 why, with the notes below.

## 8. Out of scope
- Any change to `fieldops/` or `data/`, including fixing the behaviours noted below.
- Tests for modules other than `fieldops/assign.py` (and the `store` calls it makes).
- Changes to `pytest.ini`, `requirements.txt`, or CI.

## 9. Risk and compliance
- Personal data: none. Test data is made up, with no customer names or phone numbers.
- Secrets: none.
- Data loss: the tests only write to temp files, so the real CSVs are safe.
- Rollback: delete the three new files.
- Things that look wrong, recorded and not fixed:
  - An order with no site skips the site rules (the 2014 TODO in `pick_crew`).
  - A priority 1 or 2 order falls back to the skill rule if the home crew is busy or lacks the skill.
  - Crew A is returned even if it is busy or does not exist in the crews file.
  - `assign_order` does not check crew load, and it can reassign an order that is already assigned.
  - `crew_load` changes the crew dicts it is given (it adds a `load` key).
