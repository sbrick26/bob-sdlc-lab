# Ticket
- Key: KAN-158
- Title: Move work orders from the CSV file to SQLite
- Requester: Swayam Barik
- Link: https://demo-ibm-bob.atlassian.net/browse/KAN-158

## What I understood
Work orders currently live in a single CSV file (`data/work_orders.csv`), which causes race conditions and lost edits when multiple users save concurrently. We will migrate work orders to a SQLite database (`data/fieldops.db`) using a migration script (`scripts/migrate.py`) and update `fieldops/store.py` to use SQLite while maintaining its existing function signatures. The original CSV file will remain intact as a fallback, with a clear rollback procedure documented at the top of the migration script.

## Open questions
1. Should crews also be moved to SQLite? Default: No, crews remain in `data/crews.csv` as specified in ticket scope.
2. Should the migration script handle automatic export during rollback? Default: No, the rollback note documents the manual export steps.

## Acceptance criteria
- `python scripts/migrate.py` creates `data/fieldops.db` and populates it with all orders from the CSV.
- The SQLite database contains exactly the same number of orders as the CSV file, including orders with missing site values.
- Running `python scripts/migrate.py` multiple times is idempotent and does not wipe or duplicate records.
- `./run.sh` displays the work orders table properly, and assign and close operations continue to work.
- `data/work_orders.csv` remains preserved and unmodified.
- `scripts/migrate.py` contains a step-by-step rollback note at the top.

## Test plan

- `tests/test_store.py`: Test idempotency of running migration multiple times.

## Work units

- `tests/test_store.py`: Add unit tests verifying store functions and migration.

## Out of scope
- Modifying UI or application logic in `fieldops/app.py`, `fieldops/assign.py`, `fieldops/report.py`, or `fieldops/nightly.py`.
- Migrating `data/crews.csv` to SQLite.
- Deleting or altering `data/work_orders.csv`.

## Risk and compliance

- Secrets: none
- Data loss: Prevented by keeping `data/work_orders.csv` intact and providing a rollback procedure.
- Rollback: Documented in `scripts/migrate.py` top comment; point `fieldops/store.py` back to CSV or re-export if needed.
