# KAN-160 plan

## 1. Ticket

- Key: KAN-160
- Title: Mask customer phone numbers and keep an audit trail
- Requester: Swayam Barik
- Link: https://demo-ibm-bob.atlassian.net/browse/KAN-160

## 2. What I understood

The daily report prints customer phone numbers in full. Compliance does not want that, so the report will show only `415-555-****`. Compliance also wants to see who assigned or closed any order, and when. I will add a new file, `fieldops/audit.py`. It will hold wrapper functions for assign and close. Each wrapper does the normal action, then adds one line to `data/audit.log`. The log is only ever added to. The existing assign and store code is not changed. Hooking the web screen up to the wrappers is a later ticket.

## 3. Open questions

1. The ticket's "touches" list includes `fieldops/app.py`, but the hints say wiring the web screen is a follow-up. Default: do not touch `fieldops/app.py`.
2. Should `data/audit.log` be saved in git? Default: no. It is created on first use. Tests write to a temporary file, so the real log is never touched.

## 4. Acceptance criteria

- The daily report shows every phone number as `415-555-****`. A full number never appears.
- Assigning an order through `audit.assign(...)` adds one line to `data/audit.log` with who, when, order number and what changed.
- Closing an order through `audit.close(...)` adds one line in the same way.
- The log only grows. Old lines are never changed or removed, and a new action never overwrites an earlier line.
- No phone number or customer name is written to the audit log.
- `python -m pytest tests/test_report.py tests/test_audit.py` passes.

## 5. Test plan

- Report shows only masked numbers: `tests/test_report.py` builds the report and checks that no full phone number appears and `415-555-****` does.
- Assign writes one line: `tests/test_audit.py` calls `audit.assign` and checks the line has who, when, order number and change.
- Close writes one line: `tests/test_audit.py` calls `audit.close` and checks the same.
- Log only grows: `tests/test_audit.py` makes two calls and checks the first line is unchanged and the line count went from 1 to 2.
- No personal data in the log: `tests/test_audit.py` checks the log text has no phone number or customer name.
- Test pass: run `python -m pytest tests/test_report.py tests/test_audit.py`.
- Tests use a temporary copy of the data and a temporary log file. `data/work_orders.csv` and the real `data/audit.log` are not touched.

## 6. Work units

- `fieldops/report.py`: mask the phone number in `daily_report`.
- `fieldops/audit.py` (new): `record(who, order_id, change)` adds a line to the log. `assign(who, order_id, crew_id)` and `close(who, order_id)` call the existing code, then `record`.
- `tests/test_report.py` (new): tests for the masked report.
- `tests/test_audit.py` (new): tests for the audit log.
- `CHANGELOG.md`: add one entry at the top for KAN-160.

## 7. Out of scope

- Changing `fieldops/app.py`. Wiring the web screen to the wrappers is a follow-up ticket.
- Changing `fieldops/assign.py`, `fieldops/store.py` or `data/work_orders.csv`.
- Masking phone numbers anywhere other than the daily report.
- Adding an audit entry for actions that do not go through `fieldops/audit.py`.
- Reading or searching the log.

## 8. Risk and compliance

- Personal data: the audit log holds only who, when, order number and change. It never holds phone numbers or customer names. Tests check this.
- Secrets: none.
- Data loss: the log is only added to. The wrappers do not change the stored order data beyond what `assign_order` and `update_order` already do.
- Rollback: revert the PR. `data/audit.log` is a runtime file and can be left or deleted.
