# KAN-160: Mask customer phone numbers and keep an audit trail

## 1. Ticket

- Key: KAN-160
- Title: Mask customer phone numbers and keep an audit trail
- Requester: Swayam Barik
- Link: https://demo-ibm-bob.atlassian.net/browse/KAN-160

## 2. What I understood

The daily report in `fieldops/report.py` prints customer phone numbers in full. It will show them masked, like `415-555-****`. A new `fieldops/audit.py` will wrap "assign" and "close". Each wrapper does the normal action through the existing code, then adds one line to `data/audit.log`: who, when, which order, what changed. The log only grows. `assign.py`, `store.py` and the web screen are not changed. Wiring the web screen to the wrappers is a follow-up ticket. Tests use made-up orders and a temp folder, never the real data.

## 3. Open questions

1. The ticket gives `415-555-****` as the example, but real numbers also use other area codes. Default: keep the first six digits and hide the last four digits, whatever the area code. Full numbers never show.
2. The ticket lists `fieldops/app.py` as a file it may touch, but its hints say web wiring is a follow-up. Default: leave `app.py` alone. Also, do not commit `data/audit.log`; it is created when the wrappers run.

## 4. Acceptance criteria

- The daily report shows every phone number masked as `415-555-****`, never in full.
- `audit.assign(...)` adds one line to `data/audit.log`: who, when, order, change.
- `audit.close(...)` adds one line in the same way.
- The log only grows. Old lines are never changed.
- No phone number or customer name is written to the log.
- `python -m pytest tests/test_report.py tests/test_audit.py` passes.

## 5. Test plan

Report tests are in `tests/test_report.py`. Audit tests are in `tests/test_audit.py`. Both use made-up orders in a temp folder.

- Report masks phone numbers: `test_report_masks_phone_numbers`.
- Report never contains a full number: `test_report_has_no_full_phone_number`.
- Assign writes one line with who, when, order, crew: `test_audit_assign_writes_one_line`.
- Close writes one line with who, when, order, "closed": `test_audit_close_writes_one_line`.
- A second action adds a line and leaves the first line unchanged: `test_audit_log_only_grows`.
- A refused assign (unknown crew, missing or closed order) writes no line: `test_audit_assign_refused_writes_nothing`.
- Log has no customer name or phone number: `test_audit_log_has_no_personal_data`.
- Real `data/` files are not touched: tests point `store.ORDERS_FILE`, `store.CREWS_FILE` and `audit.AUDIT_FILE` at the temp folder.

## 6. Work units

- `fieldops/report.py`: change. Mask the phone number in `daily_report`.
- `fieldops/audit.py`: create. `record(who, order_id, change)` appends one line; `assign(...)` and `close(...)` wrap `assign.assign_order` and `store.update_order`.
- `tests/test_report.py`: create. The report tests above.
- `tests/test_audit.py`: create. The audit tests above.
- `changes/KAN-160.md`: create. Two lines: what changed, why.

## 7. Out of scope

- Any change to `fieldops/app.py`, `fieldops/assign.py`, `fieldops/store.py`, `data/work_orders.csv` or `requirements.txt`.
- Wiring the web screen to the audit wrappers (follow-up ticket).
- Hiding customer names in the report.
- Reading, searching or rotating the audit log.

## 8. Risk and compliance

- Personal data: the report masks phones. The log holds no customer name or phone number. Tests use made-up data only.
- Secrets: none.
- Data loss: none. The log is opened in append mode only. Tests write to a temp folder.
- Rollback: revert the PR. An existing `data/audit.log` can be left in place or deleted.
