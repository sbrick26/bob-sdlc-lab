## 2. What I understood
The daily report currently prints full customer phone numbers, which is a compliance risk. This ticket adds a masking function to `report.py` so that every phone number is shown with the last segment replaced by asterisks (e.g. `NXX-NXX-****`). It also adds a new `fieldops/audit.py` module with a `record(who, order_id, change)` function that appends one pipe-delimited line per event to `data/audit.log`. Two convenience wrappers — `audit.assign(who, order_id, crew_id)` and `audit.close(who, order_id)` — call through to the existing `assign.assign_order` and `store.update_order` respectively, and write an audit entry each time. The web layer is not wired in this ticket; `who` is a plain string the caller supplies.

## 3. Design decisions
| # | Question | Answer | Effect |
|---|----------|--------|--------|
| 1 | Mask format | **default** — replace everything after the second hyphen with `****` | `mask_phone()` splits on `-`, keeps first two segments, appends `****` |
| 2 | Audit log location | **default** — `data/audit.log` at repo root `data/` directory | `audit.py` resolves path relative to `store.DATA_DIR` |
| 3 | "who" in audit record | **default** — plain string parameter passed by the caller | `record(who, order_id, change)` signature unchanged |
| 4 | Audit log format | **default** — pipe-delimited line with ISO-8601 UTC timestamp | `<timestamp> | who=<who> | order=<id> | change=<description>` |

## 8. Out of scope

- Masking phone numbers in stored CSV data.
- Log rotation or size limits on `data/audit.log`.
- Changes to `assign.py` or `store.py`.

## 9. Risk and compliance
- **Personal data:** phone numbers are masked in report output; raw data stays in CSV unchanged (no new exposure).
- **Secrets:** none introduced.
- **Data loss:** `audit.log` is append-only; no existing data is modified.
- **Rollback:** remove `fieldops/audit.py`, revert the two lines changed in `report.py`.
