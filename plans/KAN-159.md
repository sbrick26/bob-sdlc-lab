# KAN-159: Let dispatch run work orders by asking in plain words

## 1. Ticket

- Key: KAN-159
- Title: Let dispatch run work orders by asking in plain words
- Requester: Swayam Barik
- Link: https://demo-ibm-bob.atlassian.net/browse/KAN-159

## 2. What I understood

Dispatch wants to type one sentence in Bob, such as "show open orders at the North Substation and assign the top two to crew B", and have it done without the web screen. We add a small MCP server with three tools: list orders, assign an order, close an order. The tools call the existing FieldOps code, so they follow the same rules as the web screen. "Top" means lowest priority number first, then oldest created date.

## 3. Open questions

1. The ticket says to use FastMCP. The current `mcp` package is 2.3.0, and in 2.x that class is called `MCPServer`. Default: pin `mcp==2.3.0`, use `MCPServer`, keep the same three tool names.
2. Orders hold a customer name and phone number, which are personal data. Default: `list_orders` never returns them.

## 4. Acceptance criteria

- The server offers exactly three tools: `list_orders(site, status)`, `assign_order(id, crew)` and `close_order(id)`.
- `list_orders` returns the orders for that site and status, lowest priority number first and then oldest created date. Each order shows id, site, equipment, description, priority, status, crew and created. It never shows customer name or phone.
- `assign_order` gives the same result as the web screen. An unknown crew, a missing order or a closed order is refused and nothing changes.
- `close_order` gives the same result as the web screen. A missing order is refused. A change made through the server shows on the web screen.
- `python -m pytest tests/test_mcp_server.py` is green, and `python -m fieldops.mcp_server` starts the server.

## 5. Test plan

All tests are in `tests/test_mcp_server.py`. They run against a temporary copy of the data, never the real files.

- Three tools only: a test lists the registered tool names and checks they are exactly the three above.
- Listing and order: a test lists open North Substation orders and checks the order is priority, then created date.
- No personal data: a test checks that no customer name or phone appears in the `list_orders` output.
- Assign: tests for a good assignment, an unknown crew, a missing order and a closed order. The refused cases check the data is unchanged.
- Close: tests for a good close and a missing order.
- Same as web screen: a test makes a change through the tools, then loads `/` from the Flask app test client and checks the change is shown.
- Starts: a test imports `fieldops.mcp_server` and checks its entry point exists.

## 6. Work units

- `fieldops/mcp_server.py` (new): the MCP server and the three tools. It calls `fieldops/store.py` and `fieldops/assign.py` and copies none of their logic.
- `tests/test_mcp_server.py` (new): the tests above.
- `requirements.txt`: add `mcp==2.3.0`.
- `fieldops/README.md`: one line saying how to start it.
- `CHANGELOG.md`: one entry at the top, required by the change-log rule. It is not in the ticket's list.

Nothing else changes. `fieldops/store.py`, `fieldops/assign.py`, `fieldops/report.py` and `data/` stay as they are.

## 7. Out of scope

- Changes to `fieldops/store.py`, `fieldops/assign.py`, `fieldops/report.py` or `fieldops/app.py`.
- Changes to the data files.
- The two known weak spots in the old code: concurrent saves can lose an edit, and the web close does not check status.
- Committing `.bob/mcp.json`. It is a protected path. The config entry goes in the PR text and each person adds it to their own local file.
- Authentication, remote access or any transport other than stdio.

## 8. Risk and compliance

- Personal data: customer name and phone are never returned or logged. Tests use masked values only.
- Secrets: none. No credentials are needed.
- Data loss: assign and close write to the CSV through the existing `store` functions. The old lost-edit risk applies if two people save at once. Tests use a temporary copy.
- New package: `mcp` is on the approved list. It is pinned to an exact version.
- Rollback: revert the PR. Nothing else depends on the new file.
