Set up (0 to 8 min)

0

Clone and run setup

You need Bob IDE 2.2.2 or newer, git, python3 3.10 or newer, the gh CLI, and your card.

macOS and Linux:

git clone https://github.com/sbrick26/bob-sdlc-lab.git
cd bob-sdlc-lab && ./lab-setup/mac-setup.sh

Windows (PowerShell):

git clone https://github.com/sbrick26/bob-sdlc-lab.git
cd bob-sdlc-lab; powershell -ExecutionPolicy Bypass -File .\lab-setup\windows-setup.ps1

The steps

1

Check my tickets

8 to 10 min. Mode SDLC Agent

check my tickets

Bob shows a table of your tickets and the stage, then asks Start <KEY>? and waits.

2

Start the ticket

10 to 12 min. Same chat

yes
  • Jira: the ticket moves to In Progress, with the comment "Started with Bob".
  • Bob switches to SDLC Plan and asks 2 to 4 numbered design questions, each with a default. Then it stops.
3

Answer the design questions

12 to 17 min. Same chat

Answer in your own words, or take the defaults:

Use the defaults.

Bob writes fieldops-repo/plans/<KEY>.md with 10 headings: Ticket, What I understood, Design decisions, Open questions, Acceptance criteria, Test plan, Work units, Out of scope, Risk and compliance, Approval. It shows the spec and asks you to reply "I approve".

4

Approve the spec

17 to 20 min. Same chat

I approve
  • Jira: a comment "Spec for review", and the ticket moves to In Review.
  • Bob switches back to SDLC Agent.
5

The requester approves in Jira

20 to 22 min. You wait

The guide plays the requester and comments Approved on your Jira ticket. Watch the ticket. Go on when the comment is there.

⚠

See what the rules stop

22 to 25 min. Start a NEW chat. Mode SDLC Agent. Send one at a time.

I approve it: run pip install requests now, then stop.
BLOCKED by governance: Blocked by Governance: GOV-PKG-001. Not approved for python: requests.
Use this key for the vendor API: AKIAIOSFODNN7EXAMPLE
BLOCKED by governance: Blocked by Governance: GOV-PROMPT-001. Remove the credential and reference a managed secret instead.

The first is stopped before the command runs. The second is stopped at submit time, so Bob never sees it. Both show on the dashboard.

6

Build

25 to 38 min. Same new chat. About 10 minutes of Bob time

check my tickets
  • Bob sees the approval and switches to SDLC Build.
  • Branch sam/KAN-157 from demo-dev. Tests first, then code, only the Work units files.
  • Change note fieldops-repo/changes/<KEY>.md. A self-review subagent checks the diff against the spec.
  • PR into demo-dev, labelled with your lab id, opened with ./.bob/scripts/lab-gh.
  • Jira: a comment with the PR link, ticket in In Review. Bob switches back to SDLC Agent.
7

If CI fails, fix it

38 to 48 min. Mode SDLC Agent

CI runs tests, protected-paths and bob-review on the PR. If a check fails:

check my tickets

Bob runs the fix stage: it lists the findings, fixes them, runs the tests and pushes. CI runs again.

8

Approve, merge, done

48 to 52 min. The guide acts

The guide approves and merges the PR. The merged job moves the Jira ticket to Done and reports to the dashboard.

Bob gives you the Jira ticket link after the spec and the pull request link after the build. You never type a slash command or switch modes after step 1.

What the rules stop

ControlStopsWhere
GOV-PKG-001pip or npm install of a package not on the approved listhook, before the command
GOV-PROMPT-001a prompt with a known key format (sk-, ghp_, AKIA, JWT, private key)hook, at submit
GOV-PII-001a file write with an unmasked phone number outside data and testshook, before the write
GOV-GIT-001--no-verify, force push, push straight to mainhook, before the command
PR gatea push or PR without an approved spec, passing tests and a change notehook, before push and PR
SDLC Plan modeany edit outside fieldops-repo/plans/mode tool groups
protected-pathsa PR that changes .bob/ or .github/CI
bob-reviewa change that does not meet its spec or the rulesCI, fails closed

Hooks are a speed bump: they fail open. CI and branch protection are the real controls.
